# Mitwirken

## Am Quellcode mitarbeiten {#contributing-to-the-code}

Lesen Sie die [Hinweise für Mitwirkende](https://github.com/ccbogel/QualCoder/blob/master/docs/CONTRIBUTING.md).

### Wichtigste Regeln im Überblick {#key-rules-at-a-glance}

- **Wähle zuerst ein Issue.** Suche ein bestehendes Issue oder erstelle eines und kommentiere es, bevor du einen Pull Request eröffnest. Warte, bis das Issue dir zugewiesen wurde, bevor du mit der Arbeit beginnst.
- **Ein Pull Request, ein Commit.** Fasse deine Arbeit in einem einzigen Commit mit einer aussagekräftigen Beschreibung deiner Änderungen zusammen.
- **Benennung.** Erstelle einen eigenen Branch, benannt nach dem Issue, das du bearbeitest.
- **Lizenz.** Mit dem Einreichen eines Pull Requests stellst du deinen Beitrag unter die LGPLv3-Lizenz des Projekts („Inbound = Outbound“).

### KI-gestützte Beiträge {#ai-assisted-contributions}

Du darfst KI-Tools zur Unterstützung deiner Beiträge verwenden, bleibst aber vollverantwortlich für alles, was du einreichst.

- **Verstehe es**: Du musst jede Zeile deines Codes erklären können.
- **Teste es**: KI-generierter Code muss alle Tests und Sicherheitsprüfungen bestehen.
- **Offenlege es**: Gib im Pull-Request-Template eine KI-Unterstützungsstufe (0–5) an.
- **Verantworte es**: Du bist der Autor. Wenn eine Reviewerin fragt „Warum?“, antwortest du — nicht die KI.

KI-Tools dürfen **nicht** zur Bearbeitung von Issues mit dem Label `good first issue` verwendet werden. Diese existieren zum Lernen für Menschen.

## Zu Übersetzungen beitragen {#contribute-to-the-translation}

### Die Dokumentation übersetzen {#translate-the-documentation}

Erstellen oder bearbeiten Sie die Markdown-Dateien unter `docs/doc` im [Repository der Website](https://github.com/QualCoder-Org/qualcoder-org.github.io).

### Die Software übersetzen {#translate-the-software}

QualCoder verwendet zwei Arten von Sprachdateien:

- Gettext-Dateien (`.po` und `.mo`) für Texte der Software,
- Qt-Sprachdateien (`.ts` und `.qm`) für die Benutzeroberfläche.

Gehen Sie wie folgt vor:

1. Falls noch keine Sprachdatei vorhanden ist, erstellen Sie diese mit `python rebuild_lang.py --create --lang LANGUAGE_CODE`. Ersetzen Sie `LANGUAGE_CODE` durch den Sprachcode gemäß [ISO 639-1](https://de.wikipedia.org/wiki/Liste_der_ISO-639-Sprachcodes).
2. Aktualisieren Sie bestehende Sprachdateien mit `python rebuild_lang.py --update --lang LANGUAGE_CODE`.
3. Bearbeiten Sie die Übersetzungen in den `.po`- und `.ts`-Dateien im Sprachdateiordner `src/qualcoder/i18n`. Für PO-Dateien können Sie beispielsweise [Poedit](https://poedit.net/) verwenden.
4. Kompilieren Sie nach Abschluss die maschinenlesbaren Dateien mit `python rebuild_lang.py --compile --lang LANGUAGE_CODE`.
